# XMODEL-010 - Reconciliacion del limite Stage 3 / SongPlanV2

Base normativa: contrato de SongPlanV2 incluido como `engine-songplan-v2.schema-music-engine-4.0.0.json`, codec y validador instalados en music-engine 4.0.0, ademas del `stage-3-songplan-format-schema-v1.2.json`. El gate ejecuta el codec, la validacion musical y la comprobacion del host; no materializa MIDI.

| Area | Contrato visible | Esquema de formato | Gate local y motor | Resolucion XMODEL-010 |
|---|---|---|---|---|
| Raiz | Objeto SongPlanV2, `schema_version: "2.0"`, nombre, tempo, compas, centro, modo, estilo, arreglo y tracks | Campos raiz requeridos; propiedades adicionales prohibidas | Gate exacto; codec real | Alineado; forma estructural invalida falla |
| Comp-s | `time_signature` es texto, analizado como numerador/denominador; numerador positivo, denominador potencia de dos | Texto no vacio | Pre-gate comprueba tipo; codec del motor valida contenido | Se aclara que el esquema del objeto no es representacion aceptable |
| Secciones | `arrangement.sections[].id`, `start_bar`, `bar_count`, `energy` | Esos cuatro campos requeridos; ID y enteros/rango | Gate valida IDs/referencias b-sicas; motor detecta solapamientos | Se usa `id` en secciones y `section_id` solo como referencia |
| Asignaciones | Tracks usan `section_assignments`; assignment requiere secci-n y motivo o variacion | `section_id` requerido; `motif_id`/`variation` estructuralmente opcionales | Gate local acepta motivo o variacion; motor comprueba referencias y operaciones | Corregido gate local que exigia indebidamente ambos `section_id` y `motif_id` |
| Tipos de track | `pitched`, `drums`, `percussion`, `effect` son contratos distintos | `oneOf` de las cuatro formas, sin propiedades extra | Codec real por tipo | No hay conversion autom-tica entre drums/percussion |
| Events / timing | `bar` entero >=1; `beat` texto Fraction-compatible con beat >=1; `duration` texto Fraction-compatible y >0 | Patron l-xico de `Fraction` para beat/duration; sintaxis completa la valida el motor | Codec real `Position`/`Duration`; clave JSON duplicada se rechaza antes de parsear ordinariamente | Aclaraci-n de beat/duration; ejemplos de pruebas son fixtures sinteticos |
| Formas de duracion | `Fraction(str)` admite fraccion, entero, decimal y notacion cientifica; guiones bajos y espacios exteriores; no espacios alrededor de `/` | Patron acepta formas observadas compatibles; no intenta codificar positividad ni denominador distinto de cero | Motor real decide el valor matem-tico; `0`, negativos y denominador cero fallan | Sin umbral musical; error estructural/valor sigue separado |
| Efectos | Evento admite solo `bar`, `beat`, `duration`, opcional `id` | Objeto estricto | Gate rechaza `position`; codec tambi-n lo rechaza | Sin borrado o correcci-n autom-tica |
| Escala / cromatismo | Nota fuera de escala requiere `chromatic: true` expl-cito | Boolean opcional en evento pitched | Motor compara pitch con escala de tonic/mode; el flag debe ser booleano | Sin ajuste de pitch, escala ni flag por el adaptador |
| Percusi-n y bater-a | `drums`: `drum_voice`; `percussion`: `kit_id`, `map_id`, pareja instrument/articulation | Campos distintos por tipo | Gate valida host separado del plan; usa registro aprobado real | Solo est- aprobada la DrumExternalMap `song001_r1_steven_slate_map`; ningun PercussionMap aprobado |
| Mapas host | IDs del plan se resuelven contra configuracion host; no sustituir IDs | No aplica | host error es `HOST_CONFIGURATION_INVALID`, separado de plan | Configuraci-n percusi-n ausente produce bloqueo, no reemplazo |
| Contrato/motor | El objeto debe parsear y superar reglas estructurales y semanticas | JSON Schema basado en contrato 4.0.0 mas patron lexical de valor | Sin motor disponible: `BLOCK`; plan invalido: `FAIL/invalid_songplan_structure`; sem-ntica: `FAIL/musical_semantic_validation_failure`; host: `HOST_CONFIGURATION_INVALID` | Nunca hay PASS si el motor no fue invocado |

La autorizacion `chromatic: true` es una propiedad de evento ya definida por el contrato v1.1, no la decisi-n del adaptador. El modelo conserva la intencion congelada de Stage 2; la capa tecnica solo rechaza inconsistencias. La validacion no es juicio de calidad musical.
